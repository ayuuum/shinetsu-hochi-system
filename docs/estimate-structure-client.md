# 信越報知システム お見積構成（先方向け・組み替え版）

| 項目 | 内容 |
|------|------|
| **作成日** | 2026年8月7日 |
| **根拠** | Google Drive「信越報知システム」スプレッドシート ＋ 既存点検支援システムのコード調査 |
| **考え方** | いま使っている点検支援システムを土台に、先に「帰社後入力・紙・口頭」を減らし、そのあと見積〜請求、最後に日報・承認を一本化する |

---

## 1. ひとことで言うと

いまの困りごとは「システムが足りない」のではなく、**現場・見積・請求・日報がバラバラ**なことです。

| 順番 | 何をするか | 先方が感じる変化 |
|------|-----------|------------------|
| **第1弾（必須）** | 点検支援システムをクラウド化し、現場でも入力できるようにする | 帰社後入力・記憶頼り・二重入力が減る |
| **第2弾（推奨）** | 不備→見積→補修→請求OKまでをつなぐ | 営業・経理の追いかけ・請求漏れが減る |
| **第3弾（後段）** | 日報・承認・会計まわりを整理する | KnowledgeSuite解約・TKC前整理が進む |

## 3. なぜこの順番か（先方向け説明）

### 第1弾が先な理由
いまの点検支援システムは、すでに次を担っています。

- 案件（物件・発注者）の登録
- 点検予定・実績の管理
- 補修の状況・履歴
- 帳票の出力

ここを飛ばして見積や請求だけ作ると、**現場の入力先がまた増える**ことになります。  
だから「いまの支援システムをクラウドに移す（A1）」と「現場でも入力できるようにする（A2）」をセットで第1弾にします。

### 第2弾が次な理由
不備の共有・見積・請求が、いまは口頭・紙・本丸・BOXに分かれています。  
第1弾で点検・不備がシステムに載ったあとでないと、営業・経理への「つなぎ」が効きません。

### 第3弾が後な理由
- メンテナンス部は、すでに支援システムの実績入力が日報代わり
- 日報・承認の本丸は工事部の KnowledgeSuite
- 解約判断とセットで移す方が、使わない機能を増やさない

## 4. 先方確認で金額が変わる分岐

| 確認 | 金額への影響 |
|------|-------------|
| **本丸の見積を残す** | B1 は「連携・ステータス」中心で抑えられる可能性 |
| **本丸をやめて新システムで見積** | B1 が増額（見積書作成まで含む） |
| **現場の通信が弱い／オフライン必須** | A2 が増額 |
| **点検LEADを報告書専用として残す** | A2 は「連携」寄りで済む可能性 |
| **LEADも新システムに統合** | A2 が増額 |
| **過去何年分を移行するか** | A3 / D2 が増減 |
| **KnowledgeSuiteをいつ解約するか** | C1・C2 の着手時期が決まる |

## 6. スプレッドシートへの反映手順（短い版）

1. 新規タブ「お見積構成」を作る（既存があれば置き換え）
2. 上記 **2.1 全体表** を貼る
3. その下に **2.2 金額サマリー** を貼る
4. シート先頭に次の1行を置く：

> 見る順番：1. 改善サマリー → 2. 最終像 → 3. **お見積構成** → 4. 対象機能 → 5. 確認事項（詳細フローは必要時）

5. 確認事項 No.5（本丸）・No.18（支援システム範囲）・No.19（LEAD）は、この見積の分岐条件として残す

## 7. 先方への話し方（30秒）

> まず、いまお使いの点検支援システムをクラウドに移し、現場から入力できるようにします（第1弾）。  
> そのうえで、不備から見積・補修・請求までをつなぎます（第2弾）。  
> 日報や承認、TKCまわりは、必要なものだけ後から足します（第3弾）。  
> 必須だけなら約510万円、請求前まで入れるなら約910万円、全部で約1,300万円です。
